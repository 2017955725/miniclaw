# 本地电商测试补货 SOP

## 安全库存与补货数量
库存低于安全线说明需要调查，不代表差值就是应采购数量。补货前核实库存口径、预占量、其他渠道占用、在途量、近七天销量、供应商及交付周期。模型解释风险和提出方案，代码校验金额、权限和状态。本文是测试规则，不是商家真实供应合同。

## 人工审批与方案变更
人工审批绑定 SKU、数量、供应商、单价、总价、test 环境、Workflow 版本和商品版本。只有登录用户能批准；Agent 不能自批。修改业务输入后必须刷新调查并重新审批，旧审批不得复用。审批有效期三十分钟。审批乐观锁 revision 用于拒绝过期页面提交，与执行幂等键含义不同。

## 采购与到货入库
批准补货后创建采购补货单，此时实物库存不增加，在途量增加。只有单独登记测试到货事件才增加实物库存、减少在途量并记录库存流水。当前仅支持整单一次到货，不支持部分收货、取消采购、退货或真实供应商下单。

## 幂等重试与失败
创建采购单使用持久化幂等键、请求指纹及审批唯一约束。相同请求重试返回原结果；同键不同参数拒绝。即使换幂等键，同一审批也只能创建一张单。采购单、在途量和执行回执在一个 MySQL 事务提交；入库、库存流水和收货回执也在一个事务提交。网络失败后重试，不盲目创建新操作。
